# 评分评测与改进记录

## 评测问题

规则评分能否执行已定义的城市、全职、工作年限、资格标注与事实证据边界？本轮测的是声明的行为，不是岗位排序质量或真实投递效果。

首版包含 12 个新编写的虚构案例，与离线演示文件分开维护。预期行为由 AI 依据项目需求拟定，项目作者尚未独立复核。案例编写时能够查看当前实现，因此不是盲测或独立金标集。样本刻意覆盖边界及语言挑战，不代表真实岗位分布。

## 复现

在仓库根目录安装项目依赖后运行，不需要 API Key、招聘账号或个人数据库：

```bash
.venv/bin/python -m app.evaluation --output data/evaluation
.venv/bin/python -m app.evaluation --output data/evaluation --strict
```

默认命令用于诊断，成功写出报告即返回 0；`--strict` 在存在未满足预期时返回 1，不能用默认命令的退出码声称评测全部通过。报告目录包含逐例实际输出、预期、检查结果，以及输入、规则配置和评分实现的 SHA-256，便于追溯版本。

输入见 [scoring-eval.yaml](../../examples/scoring-eval.yaml)，执行器见 [evaluation.py](../../app/evaluation.py)，修复前完整结果见 [results.md](results.md) 和 [results.json](results.json)。建立 v1 基线时未修改生产评分规则；后续 v2 修改见迭代记录。

## 规则 v2 迭代

同一份输入和预期保持不变，12 个案例由 8/12 变为 12/12。见 [v2 结果](v2/results.md) 和 [完整输出](v2/results.json)。两个版本的输入 SHA-256 应一致，规则与实现 SHA-256 应不同。

新增 25 个语言回归检查，另加严格评测失败退出码测试，共 67 项工程测试通过。回归案例与实现同时编写，不能称为独立保留集。没有更改评分维度权重、星级阈值、目标城市或毕业年份标注规则。

- 英文数字年限识别支持 `minimum`、`at least`、`required`、`must`，以及数字区间与 `+` 写法；优先条件不作为硬性年限要求。
- 博士与履历证据匹配排除显式否定要求，按标点或转折词划分范围，保留其他分句中的正向要求。
- 目标方向配置增加 `AI Product Manager` 和 `Artificial Intelligence Product Manager`。

限制：目前是词法分句，不支持任意复杂否定、跨句指代、英文拼写数字年限或完整语义推理。一个分句同时含多个条件时仍可能误判，需要人工核实。当前只修改程序与公开测试，不自动重新评分本地真实岗位库；历史分数在后续显式重算前仍保持原值。

## 验证结论：附带限制分享

按照分析验证流程核对了案例级分母、全部检查通过才计数的规则、JSON 与报告一致性、可重复运行及严格退出码。41 项 Python 测试通过表示工程测试成功，不等于 12 项产品预期全部满足。现有依赖产生 2 条弃用警告，不影响本次运行结果。

进入“独立评测”前仍需项目作者复核标签，增加未经实现者查看的案例，记录分歧及裁决，再基于人工判断检验排序质量。当前没有真实用户效果数据，因此不声称节时、提高投递转化或商业收益。
